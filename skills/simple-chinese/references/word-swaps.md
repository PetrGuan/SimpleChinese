# 词语替换

先读懂句子，再改写。这个表不是全局查找替换表，也不是完整受控词典。
白话模式优先常用表达；严格模式只对同一概念归并用词。
完整词条种子、条号和适用范围见 [完整规则](rule-catalog.md)。

## 同一概念用同一个词

| 原词 | 常用表达 | 改写例 | 不能机械替换的情况 |
|---|---|---|---|
| 核查、查验、校验、核实 | 检查 | 核查日志 → 检查日志 | 校验和、协议校验、代码里的 `validate` |
| 执行、跑 | 运行 | 执行构建命令 → 运行构建命令 | 标识符、引用、领域内不同的执行语义 |
| 展示、呈现、展现 | 显示 | 展示错误码 → 显示错误码 | 原始 UI 文案必须逐字引用时 |
| 然而、不过 | 但是 | 然而内存增加了 → 但是内存增加了 | 原文引述 |
| 由于、鉴于 | 因为 | 由于端口占用 → 因为端口占用 | 保留条件、因果与证据强度 |
| 旨在、助力 | 用于、帮助 | 旨在导出数据 → 用于导出数据 | 原文只描述目标时，不声称已经实现 |

归并前确认含义相同。“检查证书是否过期”和“验证签名”可能是不同动作，不能仅因词典建议就统一成一个步骤。

## 写出动作或已有事实

| 原词 | 改写方向 | 改写例 |
|---|---|---|
| 赋能 | 说明帮助谁做什么 | 帮助运营查看退货率 |
| 抓手 | 方法、工具 | 用日报检查退货率 |
| 闭环 | 说明流程或结果 | 收到反馈后分配负责人，处理后通知用户 |
| 底层逻辑 | 原因、原理 | 失败原因是连接超时 |
| 颗粒度 | 具体单位或细节程度 | 按小时统计 |
| 打通 | 根据事实选择连接或同步 | 把订单同步到报表系统 |
| 链路 | 流程、调用路径 | 请求经过网关和订单服务 |
| 沉淀 | 记录、保存 | 把处理方法记录到手册 |
| 对齐 | 统一、商定 | 统一超时时间 |
| 落地 | 根据实际阶段选择实现或上线 | 新版本已经上线 |
| 搞、弄、打（泛义） | 具体动词 | 搞好证书 → 安装证书 |
| 进行、予以、加以（虚化） | 删除虚化动词 | 进行修改 → 修改 |
| 至关重要、无缝、强大 | 删掉装饰或引用已有事实 | 工具支持自动导出 |

这些例子演示表达方向，不提供可直接添加到任意文档的事实。
原文没有同步频率、处理时间或性能数字时，不能为了“具体”而编造。
保留闭环控制、链路追踪、内存对齐、化学沉淀等确有技术含义的词；概念首次出现时解释。
“打开文件”的“打”不是泛义动词，“任务正在进行”也不能删成病句。

## 情态与不确定性

| 原表达 | 如何处理 |
|---|---|
| 应该先备份 | 若原文明确是强制要求，写“必须先备份”；若是建议，保留建议强度。 |
| 或许、也许、可能 | 有已知条件时写明条件；没有依据时保留不确定性。 |
| 可能超时 | 不能改成“会超时”，也不能机械改成“可以超时”。 |
| 不建议删除 | 不能擅自改成“不能删除”；保留建议与禁止的区别。 |

第 3.2 条让要求更清楚，不授权改动事实。拿不准时保留原文，在检查报告里标记待确认。

## 删除无信息的包装

| 原表达 | 处理 |
|---|---|
| 好问题、你说得非常对 | 删掉奉承，直接回答。 |
| 值得注意的是、总的来说 | 删掉过渡词，保留后面的事实。 |
| 总而言之、综上所述 | 若只是重复前文，删掉总结句。 |
| 希望对你有帮助、让我们一起 | 删掉无任务信息的结尾。 |
| 高效便捷、安全可靠、灵活易用 | 删掉空泛形容，保留已有功能或数字。 |
| 不仅是一个工具，更是一种理念 | 删掉拔高，说明工具实际做什么。 |
| 研究表明、业内普遍认为 | 给出具体来源，或删除无来源断言。 |

安全警告和危险操作确认不属于客套话。不能因其中出现“请注意”“请确认”而删除。
