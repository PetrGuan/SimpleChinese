# 改写对比与手动试写

这里有 8 组示意改写，覆盖技术文档和对话回复。
来源：本项目在 2026-10-29 编写的示例，不是 DeepSeek 或 GPT 的实测输出。
这些例子用于说明预期行为，不证明模型性能，也不满足 issue #1 的“真实输出对比”验收项。

每组的“任务”可以用于手动试写。“改写前”是待改素材，“改写后”是参考写法，不是唯一正确答案。
数字、命令、错误和风险均来自各组给定素材，不可据此推断真实系统行为。
真实试写完成后，用未经编辑的原始模型输出补充本文件，并注明来源，不把人工润色稿称作原始输出。

## 1. 安装步骤：拆开动作

类型：技术文档，严格模式。

任务：

```text
严格模式，改写下面的安装步骤。保留所有命令和操作顺序：
首先，您需要通过运行 npm install 来对项目依赖进行安装，随后再执行 npm run build 来完成项目的构建工作，最后运行 npm start 以启动服务。
```

改写前：

> 首先，您需要通过运行 `npm install` 来对项目依赖进行安装，随后再执行 `npm run build` 来完成项目的构建工作，最后运行 `npm start` 以启动服务。

改写后：

1. 运行 `npm install` 安装依赖。
2. 运行 `npm run build` 构建项目。
3. 运行 `npm start` 启动服务。

依据：第 1.6、5.1、5.2、5.3 条。这里是执行顺序，编号列表有用，不应删除步骤。

## 7. 短回复：不用标题包装解释

类型：对话回复，即使用户说“严格”也不变成技术文档。

任务：


改写前：

```markdown
## 核心概念
**首先**，幂等就是说同一请求执行多次，结果不变。
**其次**，请求失败后重试，不会重复创建同一笔订单。
```

依据：R2、R3、R4、R5。不把“不是所有接口”当作空泛拔高而删除。

## 手动验收方法

使用 DeepSeek 和一个 GPT mini 级模型分别手动试写以上 8 个任务。
记录确切模型 ID、日期、输入提示、启用方式和未经编辑的原始输出。不要只记录“DeepSeek”或“GPT”品牌名。
完整技能方式需要同时提供 `SKILL.md` 和任务所需 references；仅粘贴主文件且缺少参考资料时不能标为完整技能。

比较无技能、完整技能、系统提示短版时，每个任务开新对话，保持原始任务与生成设置相同。
不要把本文件的参考改写放进模型上下文，否则对比不能反映独立生成。
v0.1 手动验收先检查原意、风险和数字是否完整，再看句子是否更直接、标题和列表是否必要。

公开原始输出前，去掉不该公开的凭证、私人数据或第三方受限内容；有删改的样本要明确标记，不能称为未经修改的原始文本。
本项目不会自动调用模型、花费预算或上传文档。v0.2 才加入成体系的收费基准和数字复算。
